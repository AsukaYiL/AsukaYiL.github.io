ch6：远程控制

课程作业要求复现”对被控端控制”，并把生成的被控端样本提交微步云沙箱检测。
全程在本地 VMware 隔离网络里完成，靶机是我自己的虚拟机。

0. 环境

角色 系统 IP
攻击端 Kali Linux 2026.2 10.0.0.5
被控端 Windows Server 2003 SP1（Host1B） 10.0.0.6

两台都挂在 VMware 的 NAT 虚拟网段，10.0.0.0/24。选这个网段是有意的——它是宿主内部的虚拟交换机，跑什么都出不了我这台电脑。

Metasploit Framework 6.4.135-dev。

1. 生成被控端

输出里有几行容易忽略但很说明问题：

payload 只有 355 字节，最终 exe 却有 7168 字节。

这就是 Metasploit 的 stager（分阶段加载器） 设计：exe 里塞的其实不是完整的 Meterpreter，只是一小段引导代码 + 一个 PE 壳。真正的大头（这次是 199238 字节的 stage）在连上攻击端之后才下载。

这也解释了一件事：exe 本身很干净，杀软不好抓。因为”坏”的部分根本不在文件里，是运行时才拉下来的。这是分阶段 payload 最本质的规避思路——不是免杀，是”文件里没东西可杀”。

2. 起监听

handler.rc：

两个参数值得说：

  • ExitOnSession false —— 拿到一个会话后监听不退出，方便反复测试。做实验时如果不写这句，第一个会话断开后 handler 就没了。
  • AutoRunScript .../migrate —— 上线后自动做进程迁移。原理是把 Meterpreter 的反射 DLL 注入到另一个正常进程（这次是 notepad.exe），然后结束原来那个 backdoor.exe。好处是：受害者关了 backdoor.exe 或者杀软干掉了它，会话依然在。

3. 上线，拿到 SYSTEM

NT AUTHORITY\SYSTEM —— 直接是系统最高权限，不是普通用户。

这点其实值得留意：样本是被当作服务启动的（用 psexec 投递时），而 Windows 服务默认就跑在 SYSTEM 下。同样是执行一个 exe，“用户双击”和”服务启动”拿到的权限完全不是一个量级。真实攻击里如果拿到管理员凭据，攻击者更喜欢用服务/计划任务这类方式落 payload，就是为了这一步到位。

引擎 检出名称

四个引擎的病毒名里直接写着 Meterpreter / MsfShell。也就是说，msfvenom 的默认输出带着公开可识别的特征签名，连我用的什么工具都认出来了——因为我一行免杀都没做。

剩下的大多是 Agent.gen / Genetic / Crypt.XPACK 这种通用启发式：它们并不认识 Meterpreter，只是觉得”这东西行为可疑 / 加了壳”。

而 17 个引擎没报。这组数字挺说明问题的：单一引擎的检出率就是不可靠，同一份样本换一家扫可能就是”安全”。多引擎交叉验证不是保险，是必要。

5. 一个值得单独说的问题：沙箱为什么连不上 C2

样本的 C2 写死的是 10.0.0.5:4444，那是我本地 VMware 的虚拟网段。微步的沙箱跑在公网机房，永远到不了这个地址。

所以它的动态分析里，网络行为只能是”尝试连接超时”。

但它的判定依然是恶意 / 木马。为什么？

因为沙箱判定根本不依赖”真的把 C2 连上”。它靠的是：

  1. 静态特征（PE 结构、shellcode 模式）
  2. 行为特征（进程注入、notepad.exe 这种异常子进程）
  3. 硬编码的固定 IP + 端口回连地址 —— 这本身就是后门最强的标志

这件事让我想明白一个区别：“沙箱能复现的攻击” ≠ “沙箱能判定的事情”。一份断网就失效的木马，依然是木马。

6. 踩坑记录

这部分比结论更有意思。

坑 1：Kali 的 msfconsole 直接崩

/usr/lib/llvm-21/build/ 里有两个指向父目录的软链接（Release -> ..、Debug+Asserts -> ..），Ruby 的 bootsnap 在扫描加载路径时顺着它们无限递归，直接把 msfconsole 打死。

删掉这两个链接就好了（它们只是旧版 LLVM 构建树的兼容占位，不影响任何东西）：

坑 2：msfconsole 必须 root

修完上一条，普通用户跑又报：

/usr/lib/ssl/private 是 0700 的，bootsnap 扫不进去。sudo msfconsole 才行。

坑 4：截图截出一片黑

Kali 用 nogui 启动的话，vmrun captureScreen 出来是纯黑的（3KB PNG）。必须 GUI 模式启动才有 framebuffer。

还有个细节：X 会话闲置会锁屏，锁屏后截图全是登录框。得先 xset s off -dpms 关掉屏保。

7. 如果站在防守方

把攻击链倒过来看，每一环都有对应的检测点：

攻击行为 防守侧能否发现
无签名 PE 落地 应用白名单、签名校验
进程注入 + notepad.exe 之类异常子进程 EDR 的进程行为监控
固定 IP:4444 长连接 网络侧看非标准端口、外连白名单
服务创建（psexec 投递） 审计 Event ID 7045 / 4697
SYSTEM 权限 最小权限原则、服务账户降权

还有一条最容易忽略的：出口流量管控。如果内网禁止随意外联，这类木马的回连根本建立不起来——这也解释了为什么真实企业环境里攻击者要费那么大劲做隧道和域前置。

8. 小结

这次最有价值的不是”拿到了 SYSTEM 会话”，而是三个认知：

  1. 分阶段 payload 让”文件”和”能力”分离。文件里只有 355 字节的引导器，真正的东西运行时才下载——所以静态查杀天生吃力。
  2. 进程迁移是为了活得久。把代码注入正常进程再杀掉原体，是后门对抗”用户关窗口”和”杀软清进程”的标准手法。
  3. 沙箱的判定能力和复现能力是两回事。连不上 C2 的木马依然是木马，因为”硬编码回连地址”这个结构本身就是证据。
